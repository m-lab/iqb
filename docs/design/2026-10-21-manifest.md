# IQB Manifest Publication

**Date:** 2026-10-21
**Status:** Prototype
**Builds on:** [2026-01-20-distribution.md](2026-01-20-distribution.md)

In addition to being available at `data/state/ghremote/manifest.json`, the
manifest is now published at the following public URL:

https://storage.googleapis.com/mlab-sandbox-iqb-us-central1/manifest/v0/manifest.json

The `mlab-sandbox-iqb-us-central1` bucket has been configured to enable
CORS so that web pages (including the M-Lab website) can get the manifest
without being blocked by the `Same-Origin` policy.

This is the CORS configuration:

```json
[
  {
    "origin": ["*"],
    "method": ["GET", "HEAD"],
    "responseHeader": ["Content-Type", "Content-Encoding", "Content-Length"],
    "maxAgeSeconds": 3600
  }
]
```

We applied the configuration to the whole bucket using:

```bash
gcloud storage buckets update gs://mlab-sandbox-iqb-us-central1 --cors-file=cors.json
```

The file path is `.../manifest/v0/manifest.json`. The versioned manifest scope
allows evolving the schema independently of the cache structure. The version
in `manifest.json` must match the version used in the URL path. Right now,
we use `.../manifest/v0` because `manifest.json` is currently at `0`.

Publication is currently still manual. It runs after we have published data
to GCS. This is the updated sequence of commands:

```
# 1. Re-run the pipeline to generate new parquet files
uv run iqb pipeline run

# 2. Publish new parquet files to GCS and update the manifest
uv run iqb cache push -d ./data

# 3. Publish the updated manifest to GCS
gcloud storage cp -Z --content-type=application/json \
  data/state/ghremote/manifest.json \
  gs://mlab-sandbox-iqb-us-central1/manifest/v0/manifest.json

# 4. Tweak the cache-control headers for the manifest
gcloud storage objects update \
  gs://mlab-sandbox-iqb-us-central1/manifest/v0/manifest.json \
  --cache-control=no-cache

# 5. Add the manifest, commit, and push
# [...]
```

The `-Z` flag in step 3 enables compression. GCS will serve a
compressed manifest with `Content-Encoding: gzip`. However,
`-Z` turns on `Cache-Control: no-transform`, which we
do not want. We would instead ideally want GCS to transparently
decompress when clients (e.g., `urllib`) do not automatically
do that. We address this issue in step 4, by overwriting the
object's value for the `Cache-Control` header. We use `no-cache`
because the manifest is mutable, so caches must validate whether
it changes before serving it to clients.
